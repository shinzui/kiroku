# Store identity is a schema-installed clone-shared singleton

## Context

A maintenance manifest must identify the database against which its witnesses were
reviewed. Connection labels and PostgreSQL database OIDs do not survive restores
as the same durable application identity. Rehearsal requires a production backup
to accept the same manifest. [ADR-3](0003-dedicated-kiroku-schema.md) places schema
objects in `kiroku`; [ADR-7](0007-replay-history-retention-uses-leases-and-ordered-stream-guards.md)
keeps maintenance coordination off ordinary hot paths.

## Decision

Migration `0017` installs `kiroku.store_identity`, a boolean-keyed singleton
containing one UUIDv7 generated by PostgreSQL. Read it through `storeIdentity` or
`storeIdentityTx`. It has no rotation operation. Backups and database templates
retain the identity, so a clone accepts the source's manifest identity.

The same migration reserves the complete `kiroku.event_compactions` ledger
contract. A unique raw SHA-256 manifest digest identifies an operation, with a
stored report digest, verified counts, stream-head witnesses and database-supplied
apply metadata. The ledger starts empty. Identity and ledger UPDATEs always fail;
DELETE and TRUNCATE reuse the existing hard-delete guards. These guards prevent
accidents; PostgreSQL privileges remain the authorization boundary.

No new column, trigger, lock or statement is added to ordinary append/read paths.
The ledger is accessed through the public library API rather than a new published
SQL relation.

## Consequences

A manifest can be rehearsed on a restored clone without rewriting its identity.
An independently migrated database has a new identity. Clones are deliberately
indistinguishable by identity alone, so operators still select the destination.
The immutable ledger supports durable idempotence and auditing after process
restart; it does not replace the consumer's archived event list.

## Alternatives considered

Caller-supplied labels are neither durable nor verifiable. Database OIDs and server
system identifiers change or have the wrong scope on restore. Rotating identity
on each migration would invalidate reviewed manifests without a requirement.
