# Kiroku 0.11.0.1 → 0.12.0.0: namespace subscriptions

## Precondition

The consumer resolves Store 0.12.0.0 and previously used the 0.11 family.
Inspect direct Kiroku usage and database ownership, including framework-owned
migration composition. If neither direct APIs nor an owned affected database
apply, report this edge inapplicable and succeed. Find dependency sources through
Mori; the owning project is mori://shinzui/kiroku.

## Source adaptation

Resolve `kiroku-store ^>=0.12.0.0` and `kiroku-store-migrations ^>=0.7.2.0`.
Where consumed, align `shibuya-kiroku-adapter ^>=0.7.0.0` and
`kiroku-metrics ^>=0.4.0.0` with their released dependencies. Handle
`SubscriptionTarget.CategoryNamespace Text` and
`KirokuEventSubscriptionTargetMismatch` in exhaustive matches.

Low-level complete `Notifier` construction supplies `namespaceRegistry` using
the owning runtime's registry; prefer its normal constructor. Exhaustive custom
FSM drivers handle `NamespaceWindowFetched`, `NamespaceWindowCompleted`, and
`DeliverNamespaceWindow` with their defined window/checkpoint semantics.
Preserve typed decode failures, consumer-group topology validation and existing
subscription target bindings. Since 0.11.0.1, script and public read errors retain
typed SQLSTATE/connection classifications; update catch-all-only consumers.

Namespace subscriptions are opt-in: `Category name` remains exact category.
`CategoryNamespace namespace` matches that exact category and colon-boundary
descendants, including future categories. Do not replace existing exact targets
automatically. Group members scan bounded global windows, so checkpoints may
advance past the last delivered matching event and sparse replay still traverses
unrelated global history. Notifications are hints; retain durable safety polling.

## Database cutover

Classify migration state read-only. Stop affected workers before an operator
applies migration 0016 through the consumer's existing native migration runner
using migrations 0.7.2.0, then restart Store 0.12 binaries before enabling
namespace targets. For a directly owned Kiroku database this is
`kiroku-store-migrate up`; framework consumers must use their composed runner.
Back up and rehearse on a restored clone before a persistent-database cutover.
This edge must not migrate a database containing real data automatically.

The new durable binding is `category_namespace`, with the literal namespace in
`target_category`. Older binaries can decode unknown kinds as unbound and must
not manage namespace checkpoint rows. Source rollback alone is not a safe
downgrade after those bindings exist. Rebind/reset requires stopped workers and
an explicit operator decision. Do not rewrite migration history or checksums,
drop a persistent database, or bypass target/topology refusal.

## Validate

Build and run the consumer's tests with exhaustive-pattern warnings, rehearse
migration on a disposable clone, verify unchanged exact-category behavior, and
test namespace selection/checkpoint/restart behavior only if adopting it.
In the owning repository, `nix develop -c just test` exercises the coordinated
packages; `seihou validate-blueprint blueprints/kiroku-upgrade` validates this
guidance. Report selected versions, source changes, tests and pending operator work.
