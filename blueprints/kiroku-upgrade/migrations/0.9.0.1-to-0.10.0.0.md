# Kiroku 0.9.0.1 → 0.10.0.0: subscription hardening

## Precondition

Apply this edge to a project using the store, its subscription APIs, or a database
owned by the Kiroku migration component. Discover usage and database ownership
before editing. A project with no affected surface should report this edge not
applicable and succeed. Resolve source through mori://shinzui/kiroku.

## Align the hardening cohort

The released cohort is `kiroku-store ^>=0.10.0.0`,
`kiroku-store-migrations ^>=0.7.0.0`, and `shibuya-kiroku-adapter ^>=0.6.0.0`
from mori://shinzui/kiroku/packages/kiroku-store,
mori://shinzui/kiroku/packages/kiroku-store-migrations, and
mori://shinzui/kiroku/packages/shibuya-kiroku-adapter. A downstream release may
select newer versions through a subsequent entailed edge. Update direct bounds
in every applicable stanza; do not add solver overrides or git pins.

## Adapt source and fixtures

- `ConsumerGroupSize` and `ConsumerGroup` become opaque. Replace direct
  construction with `mkConsumerGroupSize` and `mkConsumerGroup`, handling their
  `Either InvalidConsumerGroup` results. Replace integer subscription batches
  with `mkBatchSize` and stream capacities with `mkStreamBufferSize`.
- `decodeHook` now returns `Either DecodeFailure RecordedEvent` in IO. Return
  `Right` for successful decoding; use the typed failure for malformed events.
  `decodeEvents` returns `DecodedBatch` (`UnchangedBatch` or
  `TransformedBatch` containing `Decoded`/`Undecodable` items). Handle those
  results rather than discarding failures or returning a partial successful
  vector.
- Complete `SubscriptionConfigM` construction must supply `undecodableHandler`,
  `handlerStallWarnAfter`, and `targetBindingPolicy`. Prefer updating
  `defaultSubscriptionConfig`. Preserve its stop-on-undecodable behavior unless
  the application explicitly chooses another policy.
- Extend exhaustive `KirokuEvent` matches for
  `KirokuEventPublisherDecodeFailed`, `KirokuEventSubscriptionGroupSizeMismatch`,
  `KirokuEventSubscriptionTargetBound`, and
  `KirokuEventSubscriptionHandlerStalled`. Handle the new `StoreError`
  constructor `EventDecodeFailed` and terminal `StopUndecodable` outcome.
  Startup refusals share `SomeSubscriptionStartupFailure`.
- Both `KirokuAdapterConfig` and `KirokuConsumerGroupConfig` use validated
  `BatchSize` and `StreamBufferSize` capacities and gain `retryPolicy` and
  `handlerStallWarnAfter`. Prefer updates of their defaults; preserve the
  five-delivery retry policy and disabled advisory watchdog unless the
  application chooses otherwise. `KirokuConsumerGroupConfig.groupSize` and
  `defaultConsumerGroupConfig` now take validated `ConsumerGroupSize`.
- Review tests that assert migration inventory: this cohort adds 0013 and 0014.
  Never turn a failing fixture into an unreviewed checkpoint skip.

## Classify persistent databases before migration

Stop every subscription worker before applying migrations 0013 and 0014 with
the owning runner. Migration 0013 derives group size from existing member rows;
an incomplete legacy member set can infer a smaller size and then refuse startup.
Migration 0014 removes legacy `stream_name` checkpoint metadata and introduces
typed target bindings. Legacy rows begin unbound; confirm the historical target
before explicitly adopting it through the configured binding policy. Never
adopt a different target merely to suppress a startup refusal.

For an intentional topology change, stop all members and use the public
`resizeConsumerGroupTx`; it rewinds all members to the prior minimum and can
redeliver already handled events, including on a same-size resize. For an
intentional target change, use `rebindSubscriptionTargetTx` with workers stopped.
When a downstream framework owns lease rows, use its composed resize API so
checkpoint and lease state change atomically.

Use read-only evidence to establish ledger state, group membership and target
identity. Operators should back up and rehearse on a restored clone before
production changes. This edge must not apply migrations or ledger changes to a
database containing real data, rewrite historical migration SQL, delete
checkpoints, or drop the database. Disposable unshared fixtures may follow their
normal rebuild path. No existing migration checksum is rebaselined here.

## Validate

Run the consuming project's build and database-backed tests in its development
environment. In Kiroku itself, `nix develop -c cabal build all --enable-tests`
and `nix develop -c just verify` cover the changed subscription and migration
contracts. Rehearse startup, typed decode refusal and clean shutdown where used;
exercise intentional resize only on disposable data. Report exact resolved
versions, edits, checks and any persistent database work left to the operator.
